## 調查：哪個版本作為動畫基準？

1. `YUAUY_Wallpaper/Program.cs:13-16` 的入口 `Main` 首先呼叫 `Application.Run(new Form1())`；後面的原型繪製流程位於該呼叫之後，正常視窗訊息迴圈執行期間不會開始這段繪製程式。
2. `YUAUY_Wallpaper/Form1.Designer.cs:56` 將 `Load` 綁定至 `Form1_Load`；`Form1.cs:26-34` 取得 WorkerW 並呼叫 `SetParent`，但是啟動 `MainLoop(hwnd)` 的執行緒語句位於註解。`MainLoop` 本身仍在 `Form1.cs:39-229`。
3. 以 `// next screen` 至 `if (first && firstCount ...` 之間的動畫程式區塊比對兩個檔案，剔除空白、縮排與 `//` 註解後，共 86 行有效程式碼逐行一致。兩個版本的主要動畫與多螢幕選圖行為相同，**不是**兩份互斥動畫設計。
4. 外層宿主與螢幕更新仍有不同：`Form1.cs` 用表單 HWND 建立 `HWndGraphics(hwnd)`，包含顯示尺寸變更的重建流程（`Form1.cs:94-105`）；最後版 `Program.cs` 用 `HWndGraphics(00)`，顯示更新邏輯已註解。兩者都不能只因為有動畫迴圈就宣稱完整桌布成品可直接執行。
5. `ec1af8f^` 的舊版 `Program.Main` 在入口立即開始渲染、曾有不同的間隔、圖片尺寸／位置、時間曲線與混合方法。這有助於追蹤歷史，但**不是**最新版共同核心的等價性測試基準。若舊版實際畫面與最新版公式之間存在使用者未記錄的偏好，仍以使用者後續實際驗收為準。

**結論**：Rust 版採用 `master` 最新版兩份程式碼的**共同動畫核心**作為數值與行為基準；以 `Form1` 的 WorkerW、顯示器處理作為 Windows 整合參考。Windows 啟動執行流程本身必須在 Rust 重製中實作成可測試且可運作的版本。絕不藉此重寫、替換或美化原有公式。

## 舊版圖片選取器稽核與新版調整

- `YUAUY_Wallpaper/Image/ImagePicker.cs:12-19` 已有獨立 `ImagePicker` 類別與 `ImageFolderList`。`SupportFiles`（第 36-42 行）限定 JFIF、JPEG、JPG、PNG，透過 `Directory.GetFiles(folder)` 取得目錄頂層檔案（第 74 行）。
- `Next()`（第 50-67 行）先將 `_index` 加 1；到達 `_imagePaths.Length` 後歸零。同一輪依索引取圖片，可避免同一候選陣列內取到重複路徑。
- **重要差異一**：原版 `Next()` 在**每次**呼叫時用所有資料夾檔案數變動、當前選取檔案不見等條件決定是否執行 `_Refresh_imagePaths()`（第 55-61 行），而不是在每一輪耗盡後無條件重新掃描。新版依使用者指定，改成每輪耗盡後更新目錄與候選清單。
- **重要差異二**：原版 `Reset()`（第 44-47 行）只設 `_index=-1`，不會自行重新掃描。`Random_NotRepeating`（第 102-105 行）會以持續保存的 `_randomSeed` 產生排序，目錄不變時新一輪**可能仍是同一順序**。新版在每輪開始時重新建立亂數順序，輪內仍維持無重複。
- 原版 `Next()` 在 `_imagePaths.Length=0` 時回傳 `null`（第 63-66 行），但沒有可見的系統匣通知，也未針對圖片解碼失敗建立安全降級。新版特別新增零圖片渲染抑制與系統匣「沒有圖片」提示，並規定不發生無限空轉。
- 所有螢幕仍共享一個提供者；一輪取完後才可重複同一路徑。新開場若只剩 1 張有效圖，可連續完成多個輪次後繼續填滿每螢幕預定的 11 張構圖。這是取圖與開場整合規格，與原版數學動畫無關。

## 使用者批准的新啟動場景（與舊版不同）

- `Form1.cs:225-226` 與 `Program.cs:237-238` 使用一個**全程式共用**的 `firstCount` 計數器；若有 `N` 個螢幕且每次圖片載入成功，`first` 為 true 的繪製共計 `10 × N + 1` 次（計數到 `10 × N` 後，再執行一次動畫才改成 false）。沒有為各螢幕獨立計數。啟動時仍依各螢幕面積加權隨機選擇目標，因此各螢幕實際快轉次數未必是 10；部分螢幕可能較少。若 `ImagePicker.Next()` 回傳 null 則該輪不遞增計數。`for` 迴圈於 `first` 為 true 時把動畫進度增量改為 `1`（一般則為 `0.03`）。使用者指出當年的這種做法來自 GDI+ 性能限制。
- 新版 **不保留這個啟動快轉技巧**，而是**每個螢幕**先顯示一張居中的主圖，再讓該螢幕的 10 張背景圖以具有隨機時間差、可重疊進行的滑入動作停留於主圖後方：一個螢幕 11 張，兩個螢幕 22 張，依此類推。這個精確的各螢幕數量不是原版碼保證的結果，而是使用者參考原版乘以 10 的設計意圖後指定的新開場規格。此開場變更是使用者明確核准的例外，**不**擴張到正式輪播時的數學曲線與多螢幕選擇。
- 使用者已確認開場期間即使 GPU 已高負載也**忽略 GPU/CPU 使用率**，不中止／延遲主圖或背景的滑入，開場期間不採樣負載。負載門檻僅用於後續排程到期的正常輪播。

## 新功能與舊動畫的邊界

- 使用者確認所有螢幕共用圖片來源；系統整體 GPU 使用率決定下一次過場可否開始，WindowsEnv 測試時使用整體 CPU 使用率。
- 過場到期前無負載量測程序；到期時先判斷負載，確認可繪製才挑圖／繪圖；原有過場進度、曲線與螢幕權重不可更動。
- 高負載跳過一次正常輪播後，必須等待完整的 YAML 輪播間隔再檢測下一次；不在原動畫公式內加入負載條件。
