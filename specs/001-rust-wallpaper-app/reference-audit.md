## 調查：哪個版本作為動畫基準？

1. `YUAUY_Wallpaper/Program.cs:13-16` 的入口 `Main` 首先呼叫 `Application.Run(new Form1())`；後面的原型繪製流程位於該呼叫之後，正常視窗訊息迴圈執行期間不會開始這段繪製程式。
2. `YUAUY_Wallpaper/Form1.Designer.cs:56` 將 `Load` 綁定至 `Form1_Load`；`Form1.cs:26-34` 取得 WorkerW 並呼叫 `SetParent`，但是啟動 `MainLoop(hwnd)` 的執行緒語句位於註解。`MainLoop` 本身仍在 `Form1.cs:39-229`。
3. 以 `// next screen` 至 `if (first && firstCount ...` 之間的動畫程式區塊比對兩個檔案，剔除空白、縮排與 `//` 註解後，共 86 行有效程式碼逐行一致。兩個版本的主要動畫與多螢幕選圖行為相同，**不是**兩份互斥動畫設計。
4. 外層宿主與螢幕更新仍有不同：`Form1.cs` 用表單 HWND 建立 `HWndGraphics(hwnd)`，包含顯示尺寸變更的重建流程（`Form1.cs:94-105`）；最後版 `Program.cs` 用 `HWndGraphics(00)`，顯示更新邏輯已註解。兩者都不能只因為有動畫迴圈就宣稱完整桌布成品可直接執行。
5. `ec1af8f^` 的舊版 `Program.Main` 在入口立即開始渲染、曾有不同的間隔、圖片尺寸／位置、時間曲線與混合方法。這有助於追蹤歷史，但**不是**最新版共同核心的等價性測試基準。若舊版實際畫面與最新版公式之間存在使用者未記錄的偏好，仍以使用者後續實際驗收為準。

**結論**：Rust 版採用 `master` 最新版兩份程式碼的**共同動畫核心**作為數值與行為基準；以 `Form1` 的 WorkerW、顯示器處理作為 Windows 整合參考。Windows 啟動執行流程本身必須在 Rust 重製中實作成可測試且可運作的版本。絕不藉此重寫、替換或美化原有公式。

## 必須逐項保護的共同行為

| 行為 | 最新版來源與關鍵數值 |
| --- | --- |

## 使用者批准的新啟動場景（與舊版不同）

- `Form1.cs:225` 與 `Program.cs:237` 的 `firstCount < Screen.AllScreens.Length * 10` 使啟動時快速執行每螢幕約十次換圖；`for` 迴圈於 `first` 為 true 時把動畫進度增量改為 `1`（一般則為 `0.03`）。使用者指出當年的這種做法來自 GDI+ 性能限制。
- 新版 **不保留這個啟動快轉技巧**，而是先顯示居中的主圖，再讓 10 張背景圖以具有隨機時間差、可重疊進行的滑入動作停留於主圖後方。此開場變更是使用者明確核准的例外，**不**擴張到正式輪播時的數學曲線與多螢幕選擇。
- 「10 張」是每螢幕還是整個多螢幕桌面的合計，目前尚待決定；不應在實作時任意猜測。

## 新功能與舊動畫的邊界

- 使用者確認所有螢幕共用圖片來源；系統整體 GPU 使用率決定下一次過場可否開始，WindowsEnv 測試時使用整體 CPU 使用率。
- 過場到期前無負載量測程序；到期時先判斷負載，確認可繪製才挑圖／繪圖；原有過場進度、曲線與螢幕權重不可更動。
- 高負載時下一次排程時間尚待使用者確認；不在原動畫公式內加入負載條件。
